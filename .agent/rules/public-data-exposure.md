# Что уходит в браузер гостя — проверяй КЛЮЧИ ответа, а не намерения

Лендинг работает **без авторизации**: `POST /public/clubform` (`get_landing`, `submit_lead`, `track_view`) и `POST /public/clubform-event` открыты для всех, и любой ответ этих ручек — публичный документ.

**Тронул SELECT или Code-ноду в WF `CvOZzrg4h5MIR8eS` / `GNeHza7gK9CrsvAz` — сделай запрос и прочитай СПИСОК КЛЮЧЕЙ ответа:**

```bash
curl -s -X POST https://n8n.lootarena.ru/webhook/public/clubform \
  -H 'Content-Type: application/json' -d '{"action":"get_landing","slug":"<slug>"}' \
  | python3 -c "import sys,json; d=json.load(sys.stdin); r=d[0] if isinstance(d,list) else d; print(sorted(r.keys()), sorted(r.get('club',{}).keys()))"
```

## Кейс, из-за которого правило появилось (16.08.2026)

Ответ на `submit_lead` содержал `chat_id: "-1003453686289"`, `thread_id` и `notify_bot` — адрес Telegram-чата клуба и имя бота, который туда пишет. **Утечка пришла не из SELECT, а из топологии:** от ноды `Format Submit` расходятся ДВЕ ветки — `Response` (гостю) и `Notify Gate` → Telegram (клубу), — их поля лежат в одном item, а нода ответа стояла на `respondWith: allIncomingItems`, то есть публиковала item целиком. Починено фильтром служебных ключей в `Response`; форма ответа (массив) сохранена.

⚠️ **Логу выполнения n8n тут верить нельзя:** нода `Respond to Webhook` показывает во вкладке output свой ВХОД, а не отправленный HTTP-ответ — после фикса `chat_id` в логе виден по-прежнему, хотя `curl` его уже не получает. Проверка = только внешний запрос.

## Что искать в ответе лендинга

- **Секреты клуба** — `langame_token_master`, `langame_token_public`, `langame_url`, ключи интеграций. `get_landing` джойнит `erp_clubs`, где они лежат соседними колонками: `SELECT c.*` здесь запрещён, перечисляй поля (сейчас — имя, адрес, часы, аватар, обложка, соцсети, валюта).
- **Внутренняя маршрутизация** — `chat_id`, `thread_id`, `notify_bot`, адреса вебхуков.
- **Условия выдачи подарка** — `offer_config.eligibility`, пороги, лимиты антиспама: зная правило, его проще обойти. Отдаём только сам подарок (`gift`) и причину отказа текстом (`gift_reason`), без внутренних порогов.
- **Чужие заявки и гости** — ответ касается только текущей отправки; телефоны, имена и `submission_id` других заявок наружу не едут.
- **Ключи капчи** — публичный `captcha_client_key` отдавать можно (он и так в HTML), `captcha_server_key` — никогда.

## Когда обязательно перепроверить

- добавил поле в SELECT публичной ноды или перешёл на `SELECT *`;
- рядом с ответом появилась вторая ветка (уведомление/лог/аналитика) — её параметры окажутся в том же item;
- нода ответа стоит на `allIncomingItems`;
- SQL-функция начала возвращать новые ключи (`clubform_submit_lead` отдаёт их в общий объект и для лендинга, и для Telegram).
