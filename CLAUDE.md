# ClubForm (лид-формы) — инструкции для Claude

Публичные мини-лендинги клубов: `form.lootarena.ru/<slug>`. Vite + React + TS + Tailwind 4, бэкенд — n8n (`POST /public/clubform`, `POST /public/clubform-event`) + Postgres. Деплой через Dokploy, отдельно от ЕРП.

**Отвечай на русском.** Правила проекта лежат в [`.agent/rules/`](.agent/rules/) (безопасность, чек-листы, деплой, самообучение), контекст — в [`.agent/specs/`](.agent/specs/). Серверная часть форм (SQL-функции `clubform_*`, workflow `CvOZzrg4h5MIR8eS`) живёт в репозитории ЕРП — правя выдачу подарка или ответ ручки, синхронизируй ОБА репо.

## Trip-wires

- **Ответ публичной ручки собирай списком полей и глазами проверяй, что в нём лежит.** Утечка приходит не из SELECT, а из топологии: от одной ноды расходятся ветка ответа и ветка уведомления, поля лежат в одном item, `allIncomingItems` публикует всё — так в браузер гостя уходил `chat_id` Telegram-чата клуба (16.08.2026). Логу выполнения не верь: `Respond to Webhook` показывает свой ВХОД, а не HTTP-ответ. → [`.agent/rules/public-data-exposure.md`](.agent/rules/public-data-exposure.md)
- **Маска и валидация телефона — по стране клуба** (`club.currency`: RUB → +7, KZT → +7 7XX, BYN → +375, KGS → +996, UZS → +998), логика в [`src/utils/phone.ts`](src/utils/phone.ts). Коды должны совпадать с `lib/currency.ts` (CLUB_CURRENCIES) в ЕРП. Маска без проверки оператора пропускает опечатку в одну цифру — и подарок бронируется на номер, которым гость не владеет.
- **Экран успеха обязан объяснять, почему подарка нет** (`giftReason`: `already_gifted` / `not_eligible` / `no_gift`, `prevGiftState` для судьбы прошлого подарка). Молчаливое «Вы записаны!» заставляет гостя заполнять форму снова — именно так набегали повторные заявки.
- **Про инвентарь ничего не обещай вслепую:** прошлый подарок мог быть потрачен или сгореть. Кнопку в приложение показывай только при `prevGiftState` = `active`/`awaiting_reg`.
- **`vite build` не делает typecheck** — перед «готово» гоняй `npx tsc --noEmit`.
